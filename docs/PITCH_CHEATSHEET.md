## 🎤 1. Питч (30 секунд / Главная идея)

«Мы разработали **KMG AI Security Agent** — гибридный ИИ-агент для автоматизированного аудита безопасности кода в CI/CD. 

Наше главное преимущество перед стандартными сканерами — **100% детерминированность вынесения вердикта** и проверки всех 8 требований ИБ Республики Казахстан (ИБ-01...ИБ-08). Мы используем синтаксический индекс воркспейса для гарантированного отсутствия галлюцинаций LLM, а языковую модель — для экспертных рекомендаций и анализа контекста. Решение выдаёт отчёты в стандартах JSON, SARIF 2.1.0 и Markdown, полностью готово к встраиванию в GitHub Actions и Docker.»

---

## 💡 2. Ключевые фишки решения (Почему мы лучшие)

### 1. **Zero-Hallucination Architecture (Без галлюцинаций LLM)**
- LLM **НЕ принимают решение** о прерывании билда (Exit Code 0 / 1 / 2).
- Вердикт вычисляется детерминированным модулем `policy.service.ts` по математической матрице находок и соответствия 8 требованиям ИБ.

### 2. **Покрытие всех 8 требований ИБ (п. 4.5 ТЗ)**
- **ИБ-01** (Разграничение доступа к админке)
- **ИБ-02** (Проверка сессии/токена на сервере)
- **ИБ-03** (Защита каналов TLS)
- **ИБ-04** (Криптозащита ПД при хранении)
- **ИБ-05** (Защита локальных журналов)
- **ИБ-06** (Нормативная база РК: Закон №418-V, Закон №94-V, Единые требования №832)
- **ИБ-07** (Сквозное журналирование действий пользователей и СУБД)
- **ИБ-08** (Контроль выгрузки ПД)

### 3. **Многоуровневый Defense-in-Depth пайплайн**
1. **Security Engine (Python / FastAPI)**: Мульти-сканирование Semgrep (SAST), Gitleaks (секреты), Trivy (зависимости).
2. **Deterministic IB Checkers**: Проверка архитектурных шаблонов по всему воркспейсу (межфайловый анализ).
3. **AI Reasoning Layer**: Обогащение находок понятными объяснениями и пошаговыми рекомендациями по устранению.

### 4. **Интеграция с GitHub и CI/CD «Из коробки»**
- **Exit codes**: `0` — пройдено, `1` — заблокировано (критические уязвимости/нарушения ИБ), `2` — ошибка сканирования (неполный анализ не может быть равен `PASS`).
- **PR Commenting**: Автоматическое форматированное сообщение в Pull Request.
- **Индустриальные отчёты**: `kmg-results.sarif` для GitHub Code Scanning, `kmg-report.md` для ИБ-специалистов, `scan_results.json` для автоматики.

## 💬 5. Ответы на возможные каверзные вопросы жюри

* **В: «Что если LLM нагаллюцинирует уязвимость или пропустит её?»**  
  *О: Наша архитектура гибридная: поиск уязвимостей и проверка ИБ выполняются детерминированными сканерами (Semgrep, Gitleaks, Trivy) и синтаксическими чекерами воркспейса. LLM используется только для формирования понятного описания и рекомендаций для разработчика, не влияя на Exit Code.*

* **В: «Как ваш агент учитывает специфику законодательства РК?»**  
  *О: В модуль `ib06-regulatory-references.ts` встроена проверка нормативной базы РК (Закон «О кибербезопасности» №418-V, Закон «О персональных данных» №94-V, Постановление Правительства №832). Агент проверяет наличие ссылок и соответствие архитектуры кодексам РК.*

* **В: «Как агент справляется с большими репозиториями?»**  
  *О: Мы реализовали ограничение контекста: батчинг находок, MAX_FILE_BYTES (400KB), дедупликацию и дедлайн-таймаут (480s). Сканеры работают параллельно.*
