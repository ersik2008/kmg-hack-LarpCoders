# Ограничения

Честный перечень того, чего агент не делает и чего не может доказать.

Навигация: [README](README.md) · [SECURITY_REQUIREMENTS](SECURITY_REQUIREMENTS.md) ·
[LLM](LLM.md) · [SECURITY](SECURITY.md)

## Основное ограничение

Агент выполняет **статический** анализ. Он делает выводы о коде и конфигурации
по их тексту, не запуская приложение. Отсюда следует принципиальное
разграничение.

### Что может быть установлено статически

| Свойство | Как |
|---|---|
| Наличие вызова конкретной функции или библиотеки | поиск по шаблону, разбор AST в Semgrep |
| Отсутствие какого-либо механизма в коде | отсутствие любых его признаков во всём проекте |
| Значение, жёстко записанное в исходном коде | шаблон + проверка контекста |
| Версия зависимости и наличие для неё известной уязвимости | сопоставление манифеста с базой уязвимостей |
| Присутствие секрета в тексте файла | энтропийный и шаблонный анализ |
| Синтаксически видимый поток от параметра запроса к опасному вызову | правила потока данных Semgrep в пределах функции |
| Значения параметров в конфигурационном файле | разбор конфигурации |

### Что не может быть установлено без выполнения

| Свойство | Почему |
|---|---|
| Что защищённый маршрут действительно отвергает запрос без токена | требуется обращение к работающему сервису |
| Какая версия TLS согласуется фактически | зависит от библиотеки, версии ОС, настроек балансировщика |
| Что запись аудита действительно создаётся при операции | требуется наблюдение за побочным эффектом |
| Что механизм не обходится через альтернативный путь | требуется полный перебор путей исполнения |
| Поведение при конкретных входных данных | требуется исполнение |
| Конфигурация, задаваемая переменными окружения при развёртывании | значения вне репозитория |
| Настройки, задаваемые во внешней системе | вне репозитория |
| Реальные права доступа к файлам после развёртывания | зависят от среды |
| Сохранность гарантий при генерации кода во время выполнения | код отсутствует в исходниках |

Практический вывод: по каждому требованию ИБ агент может доказать **наличие
механизма в коде** и **его отсутствие**, но не может доказать **корректность
работы механизма во время выполнения**. Полная проверка соответствия требует
динамического тестирования, которое в текущей реализации отсутствует.

## Ограничения анализа кода

| Ограничение | Следствие |
|---|---|
| Межпроцедурный анализ потоков данных отсутствует | поток «параметр запроса → вспомогательная функция → SQL» может быть пропущен |
| Межмодульный анализ отсутствует | нарушение, разнесённое по нескольким файлам, не собирается в цепочку |
| Динамическая диспетчеризация не разрешается | `handlers[name](req)` не связывается с конкретным обработчиком |
| Метапрограммирование не поддерживается | маршруты, регистрируемые циклом или фабрикой, не перечисляются |
| Файлы `.md` не читаются вовсе | ИБ-06 проверить нечем |
| Обход дерева в `ArchitectureService` останавливается на 800 файлах | граф архитектуры на крупных проектах неполон |
| Сбор признаков контролей: не более 8 совпадений на контроль | оценка покрытия невозможна — критично для ИБ-07 |
| Файлы крупнее 400 КБ не читаются при сборе признаков | признак в большом файле не найден |
| Guard в режиме CI: не более 400 файлов и 512 КБ на файл по умолчанию | при `paths: all` крупный репозиторий проверяется не полностью |
| Бинарные файлы пропускаются | встроенный секрет в бинаре не найден |
| Зашифрованная конфигурация не разбирается | содержимое недоступно |

## Ограничения, связанные с языковой моделью

| Ограничение | Следствие | Что смягчает |
|---|---|---|
| Возможны галлюцинации | ссылка на несуществующую строку или файл | ссылки вне собранных признаков отбрасываются; вердикт CI от модели не зависит |
| Невоспроизводимость формулировок | повторный прогон даёт иной текст обоснования | `temperature: 0.1`; детерминированная часть результата воспроизводима |
| Ограниченный контекст | модель никогда не видит проект целиком | полнота обеспечивается сканерами, не моделью |
| Зависимость от внешнего сервиса | при недоступности Groq AI-этап пропускается | находки сканеров и вердикт сохраняются |
| Дневной лимит токенов | на больших проектах часть находок может остаться без разбора | дедупликация, группировка, адаптивное окно |
| Текст вердикта не валидируется | упомянутые в обосновании файлы и строки не проверяются | TODO |
| Чувствительность к инъекции промпта | искажение текста обоснования | решение от модели не зависит; см. [LLM.md](LLM.md) |

Существенно: языковая модель в этой системе — **инструмент интерпретации, а не
обнаружения**. Она не находит уязвимости самостоятельно; она объясняет и
классифицирует то, что нашли детерминированные инструменты, и оценивает
собранные признаки контролей.

## Ограничения, связанные со сканерами

| Ограничение | Следствие |
|---|---|
| Semgrep находит только то, на что есть правило | классы уязвимостей вне набора правил не обнаруживаются |
| Покрытие правилами различается по языкам | JavaScript/TypeScript и Python покрыты полнее прочих |
| Gitleaks работает с `--no-git` | секреты, удалённые из рабочего дерева, но оставшиеся в истории, не находятся |
| Trivy зависит от базы уязвимостей | при устаревшей базе свежие CVE не обнаруживаются |
| Trivy сопоставляет версии, а не достижимость кода | уязвимость в неиспользуемой зависимости отмечается как находка |
| Встроенный резерв основан на регулярных выражениях | высокая доля ложных срабатываний, применяется только при недоступности движка |
| Дедупликация между сканерами отсутствует | одна проблема, найденная двумя инструментами, даёт две записи |

## Ограничения по требованиям ИБ

Главное ограничение решения в контексте хакатона.

| ID | Ограничение |
|---|---|
| ИБ-01 | Перечень административных маршрутов не строится; соответствие «маршрут ↔ guard» не устанавливается. Вывод возможен лишь о наличии авторизации где-либо в проекте |
| ИБ-02 | Покрытие защищённых конечных точек не вычисляется |
| ИБ-03 | Конфигурация веб-сервера не разбирается; версия TLS и шифронаборы не проверяются; продакшн- и dev-конфигурация не различаются |
| ИБ-04 | SHA-256 и прочие быстрые хеши общего назначения не детектируются как нарушение; параметры KDF не проверяются; схема БД не анализируется |
| ИБ-05 | Проверка отсутствует полностью |
| ИБ-06 | Проверка отсутствует полностью; документация не читается ни одним компонентом |
| ИБ-07 | Оценка покрытия проекта не выполняется — именно то, что п. 4.5.7 объявляет нарушением; журнал событий СУБД не проверяется |
| ИБ-08 | Проверка отсутствует полностью |

Подробности по каждому — [SECURITY_REQUIREMENTS.md](SECURITY_REQUIREMENTS.md).

## Ограничения интеграции с CI/CD

| Ограничение | Следствие |
|---|---|
| Код завершения `2` не реализован | оператор CI не отличает нарушение безопасности от сбоя инфраструктуры |
| Значение `paths` по умолчанию — `changed` | при использовании composite action без явного `paths: all` сквозные требования не проверяются |
| Корректного завершения по лимиту времени нет | при срабатывании `timeout-minutes` частичный отчёт не формируется |
| Markdown-отчёт как файл-артефакт не формируется | доступны только job summary и комментарий в PR |
| Перечень нарушенных требований ИБ в журнале отсутствует | п. 4.3.5 ТЗ выполнен частично |
| Путь через webhook требует доступности backend из интернета | для локального запуска неприменим |

## Ограничения измерений

Замеры производительности не проводились. Единственный доступный показатель —
`duration_ms` в ответе движка, покрывающий только этап сканирования. Методика
измерений — [PERFORMANCE.md](PERFORMANCE.md#методика-измерения).

Метрики качества обнаружения (доля пропусков и ложных срабатываний) не
измерялись: фикстуры [security-test-repository/](../security-test-repository/)
существуют, но не подключены к автоматическому прогону и не имеют файла
ожидаемых результатов.

## Ограничения среды

| Ограничение | Следствие |
|---|---|
| Требуется доступ к `api.groq.com` | без него AI-анализ не выполняется |
| Требуется доступ к `github.com` | для клонирования и публикации статусов |
| Образ security-engine занимает 2–3 ГБ | требования к месту и времени сборки |
| Результаты зависят от версий Semgrep, Gitleaks и Trivy | прогоны на разных сборках образа могут отличаться |
| База уязвимостей Trivy фиксируется на момент сборки образа | без пересборки перечень CVE устаревает |
| Проверяемая среда отличается от продакшн-среды | переменные окружения, секреты и настройки развёртывания недоступны |

## Чего агент не заявляет

Формулировки, которых в этой документации нет и которые были бы некорректны:

* «обнаруживает 100% уязвимостей» — доля обнаружения не измерялась и заведомо
  не полна;
* «гарантирует соответствие требованиям ИБ» — четыре требования проверяются
  частично, три не проверяются вовсе;
* «отсутствие находок означает безопасность проекта» — отсутствие находок
  означает лишь то, что применённые правила не сработали;
* «проверка заменяет аудит безопасности» — статический анализ является
  дополнением к аудиту, а не его заменой;
* «вердикт PASS подтверждает корректность механизмов защиты» — `PASS` означает
  отсутствие находок при завершённых сканерах.

Единственное утверждение, которое система делает добросовестно и которое
подкреплено кодом: **вердикт `PASS` невозможен, если проверка не была выполнена
полностью.** Незавершённый сканер, неготовая рабочая область или отключённые
сканеры приводят к `SCAN_PARTIAL` / `SCAN_INCOMPLETE`, и в CI это даёт ненулевой
код завершения. Это свойство закреплено тестами 3–7 в
[scan-correctness.spec.ts](../backend/test/scan-correctness.spec.ts).
